# Technical rules (testing)

Applies when editing testing docs or shared test harness guidance. On overlap with the project master [`../technical-rules.md`](../technical-rules.md), **this file wins**; otherwise the master applies.

- Shared bar already in the master: **testing as we build**, unit tests + per-area helpers, eventual e2e.
- Doc layout → master **Testing topic doc shape** + [`documentation-rules.md`](./documentation-rules.md).
- Map / entrypoints → [`contents.md`](./contents.md), [`overview.md`](./overview.md), [`services/contents.md`](./services/contents.md), [`deployment-tool/contents.md`](./deployment-tool/contents.md), [`frontend/contents.md`](./frontend/contents.md) (placeholder).
- Deployment Tool run/CI conventions → [`../deployment/deployment-tool/cli/testing.md`](../deployment/deployment-tool/cli/testing.md); depth inventory → [`deployment-tool/contents.md`](./deployment-tool/contents.md).
- The `testing/` module **may import product code** from [`services/`](../../services/) — it is a central home for shared test methods, constants, and helpers, and the harness and soak tools need real product values (config, NATS, placement, auth) to do their job. The `services` ↔ `deployment-tool` no-cross rule governs what ships in a binary; test code is local and never in a built image, so it is not bound by it.
- **Only `_test.go` files under `services/**` may import `eve-industry-planner/testing/…`.** `services/go.mod` requires the module with `replace ../testing`, but service images build with Docker context `./services` ([docker-bake.hcl](../../deployment-tool/internal/images/docker-bake.hcl)), so that directory is absent in the builder. Go's module pruning never reads a replaced module's `go.mod` when no non-test package imports it, so `go build` succeeds — a normal file importing it puts the module in the production build graph and the image build fails. Beware a helper file without the `_test.go` suffix (e.g. `worker/ratelimiter/test_helpers.go`): it compiles as product code.
- Service Dockerfiles have **no separate `go mod download` layer** — that step reads every replacement and fails on the absent path. Dependencies come from the `/go/pkg/mod` cache mount on the build step. Do not reinstate a bare `go mod download`.
- A fake used only by one product package's own tests is not shared code: it belongs beside that package (e.g. [`capacity-controller/cluster/clusterfake`](../../services/capacity-controller/cluster/clusterfake/)), not here.
- Do not invent a second global test style here. Shared Go harness / ops-soak **code** lives under [`testing/`](../../testing/) (import `eve-industry-planner/testing/…`). Shared cross-soak helpers: [`testing/harness`](../../testing/harness) (`ConnectNATS`, `AsynqRedisOpt`); polling: [`testing/wait`](../../testing/wait) (`For` for tests, `Until` for long-running waits) — do not hand-roll a deadline/sleep loop. Test key material: [`testing/keys`](../../testing/keys) — never re-type a key literal in a test. WS client SoT: [`testing/ws_soak/lib`](../../testing/ws_soak/lib). Document each harness area as its own topic — start: [harness.md](./harness.md).
- Ops soak (`testing/ws_soak`): default edge URL is Traefik; always override `LOG_LEVEL=warn` (or higher) in the docker run; fanout wall = ramp (connect) + duration (publish); report `pending` is harness expects, not NATS/WS queues — details in [harness.md](./harness.md).
- Capacity soak (`testing/capacity_soak`): prefer host + `DOCKER_HOST` for desired replicas; shorten operator `scale_*` for demos; `-phase all|up|down`; worker uses `harness.AsynqRedisOpt` / `CapacitySoakNoop`; websocket/api call soaklib hold with `Accounts==Clients` — details in [harness.md](./harness.md) § Capacity soak.
